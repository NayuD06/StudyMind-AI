# CI/CD bằng GitHub Actions

Trạng thái: đã commit cùng thư mục `doc/` · Ngày: 12-10-2026

Hai workflow trong `.github/workflows/`. Chúng chỉ bắt đầu chạy sau khi được push lên GitHub.

## CI – `ci.yml`

Chạy mỗi lần push lên `main` hoặc mở pull request. Ba nhóm việc chạy song song:

| Job | Kiểm tra gì |
|---|---|
| `frontend`, `admin` | `npm ci` → `npm run lint` (oxlint) → `npm run build` (kiểm tra kiểu TypeScript rồi build) |
| `backend` | `prisma validate` → áp toàn bộ migration lên một MySQL 8.4 trống → so `schema.prisma` với migration → `npm run build` |
| `ai-service` | Kiểm tra cú pháp Python (`compileall`) |

Vài điểm đáng biết:

- **Bước so schema với migration** bắt được lỗi hay gặp: sửa `schema.prisma` mà quên chạy `npm run db:migrate` để tạo migration.
- MySQL trong CI là container tạm, tự hủy sau mỗi lượt. Mật khẩu `ci-only-root` viết thẳng trong file là của container đó, không phải của môi trường thật nào. CI không cần secret nào.
- AI service chỉ được kiểm tra cú pháp: cài đủ thư viện (torch, sentence-transformers) nặng vài GB, không đáng cho mỗi lần push.
- Dự án **chưa có test tự động**, nên CI hiện chỉ bảo đảm mã lint sạch, đúng kiểu, build được và migration áp được. Khi có test thì thêm một bước `npm test` vào job tương ứng.

## CD – `release.yml`

Chạy khi đẩy một tag dạng `v1.0.0`:

```bash
git tag v1.0.0
```

```bash
git push origin v1.0.0
```

Workflow build lại ba phần rồi tạo một GitHub Release kèm ba file:

| File | Bên trong |
|---|---|
| `frontend-v1.0.0.zip` | Trang sinh viên đã build (file tĩnh) |
| `admin-v1.0.0.zip` | Trang quản trị đã build (file tĩnh) |
| `backend-v1.0.0.zip` | Mã đã biên dịch, `prisma/`, `package.json`, `package-lock.json`, `.env.example` |

**Chưa có bước tự đưa lên máy chủ.** Dự án chưa chọn nơi triển khai, nên phần CD dừng ở đóng gói bản phát hành. Khi đã có nơi chạy (VPS, Render, Railway, Vercel...), thêm một job triển khai vào `release.yml` và đặt thông tin đăng nhập của nơi đó trong GitHub Secrets, không viết vào file.

## Đã kiểm tra tới đâu

- Trên máy: `prisma validate`, lệnh so schema với migration ("No difference detected"), lint và build của cả ba app đều đạt.
- **Chưa kiểm tra:** bản thân hai file workflow chưa chạy trên GitHub. Lượt đầu tiên sau khi push cần xem tab Actions; nếu có bước hỏng thì sửa theo log.

## Xem kết quả

Tab **Actions** trên trang GitHub của repo. Dấu tích xanh cạnh mỗi commit là CI đạt; dấu đỏ thì bấm vào để xem bước nào hỏng.
